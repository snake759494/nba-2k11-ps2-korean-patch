# 기술 설명

## 디스크와 VC 아카이브

- 원본은 DVD ISO(2,048바이트 섹터)이며, ISO9660과 UDF 파일 시스템이 함께 들어 있습니다(UDF 파티션 시작 섹터는 268). 게임 데이터는 루트의 `0.`~`3.` 네 파일에 나뉘어 있고, 이 넷이 하나의 VC 아카이브를 이룹니다.
- VC 헤더 구조
  - 항목 수: `0x15f2`
  - 파트 크기: `0xc + 4i`
  - 항목 표: `0x9c`부터 `(해시, 크기, 섹터)` 형식. 섹터 번호는 0x80000 섹터마다 다음 파트로 넘어갑니다.
- 패치한 항목은 마지막 파트 `3.` 뒤에 덧붙이고 항목 표를 고칩니다. 그래서 빌드할 때 `3.` 파일을 ISO 끝(UDF 앵커가 있는 마지막 섹터 바로 앞)으로 옮기고, ISO9660과 UDF의 파일 위치·크기를 다시 씁니다(`tools/build.py`, `tools/iso.py`).
- 항목은 LZ 압축 단위로 이어져 있습니다.
  - 각 단위는 0x20바이트 헤더(마법수, …, `FEEDBEEF`)로 시작합니다.
  - 압축 데이터 앞에는 `usize, 1, nb` 헤더가 붙습니다.
  - **압축한 단위의 크기는 16바이트 배수여야 합니다.** 맞지 않으면 부팅 중에 멈춥니다.
  - 압축기는 `tools/vcx`(C#)와 `tools/lz.py`입니다.

## 텍스트

| 위치 | 해시 | 내용 | 방식 |
| --- | --- | --- | --- |
| `_TDB` | `d7c5aaac` | UI 문자열 DB(메뉴·안내·오류·어소시에이션 등) | 새로 작성. 0x60부터 `(해시, 자기상대 오프셋)` 표, 포인터 = `&필드 − 1 + 값`. 개수는 0x54 |
| `ROST` | `480fae44` | 로스터: 선수·코치 이름, 팀명, 연고지, 경기장, 대학, 국가, 별명 | 0x7c6a0부터 끝까지가 문자열 풀. 같은 크기 안에서 다시 쓰고, 4바이트 정렬 참조 필드를 모두 새 위치로 고침 |
| 실행파일 `SLUS_219.36` | – | UTF-16 UI 문자열 | 제자리(같은 길이 이내) |
| MRK 6개, `LITE` | – | 온라인 메뉴·퀴즈 등 | 제자리 |

- 실행파일 문자열은 `0x7f0000`~`0x850000` 구간의 문자열과, 공백이 들어간 10자 이상 문장만 바꿉니다. 2자 이하 문자열은 따로 확인한 표(`translation/fix/elf_short.json`)에 있는 것만 바꿉니다. `Li`·`GP` 같은 짧은 패턴이 코드 바이트나 코드 표 안에 있는 것까지 바꾸면 부팅 중에 멈춥니다.
- **경기 중 멈춤(v1.0 → v1.1 수정)**
  - 번역하면 `_TDB`가 원본보다 작아집니다(218,448 → 약 136KB). 이렇게 작아지면 경기에 들어간 뒤 얼마 지나지 않아 멈출 때가 있었습니다(시험에서 약 50%).
  - 원문을 그대로 다시 쓴 빌드와, 같은 번역을 원본 크기까지 0으로 채운 빌드는 멈추지 않았습니다. 그래서 `_TDB`는 항상 원본 크기 이상으로 채웁니다.
  - 그 밖에도 원본처럼 원문이 다른 항목은 번역이 같더라도 문자열을 따로 둡니다. `_TDB`와 `ROST` 모두 해당합니다.

## 한글 출력

- 게임 문자열은 UTF-16입니다. 게임이 문자 코드를 **부호 있는 16비트**로 비교하기 때문에 0xAC00 이상의 한글은 그대로 쓸 수 없습니다. 그래서 한글 음절을 `0x3400 + 순번`(자주 쓰는 순)으로 바꿔 넣습니다(`tools/ktext.py`). 번역에 쓰인 음절은 975자입니다.
- 폰트는 `LITE`(`55fc18a7`) 묶음 안의 FONT 7종입니다(Arial 11, Arial 13/15 Bold, Arial Black 15 Italic/17/20/25).
  - 폰트 구조체 주요 필드:
    - `+0x00` 첫·끝 코드
    - `+0x04`/`+0x08` 범위 표
    - `+0x20` TEX0
    - `+0x38` 런타임 텍스처 포인터
    - `+0x48` CLUT
    - `+0x4c` 텍스처 크기
    - `+0x54` 텍스처 바이트
  - 글리프 레코드는 0x60바이트이며, 진행 폭, 정점 4개, `+0x50` UV 순입니다.
- **글꼴 텍스처 크기는 원래대로 유지합니다(v1.2).** 경기 중에 쓰는 글꼴 텍스처를 키우면(v1.1은 7장 합계 +220KB) 텍스처 관리자의 VRAM 배치가 바뀝니다. 그러면 VIF1이 인터럽트 비트에서, GIF가 PATH3 마스크 상태에서 서로를 기다리며 멈춥니다. EE는 `0x4d02ac`에서 프레임 완료 플래그를 기다리는 상태로 남습니다. 한글 칸은 빈 공간과 라틴 확장 문자(0x80~0xFF, ©·®·°·ð 제외) 자리에 1픽셀 단위로 배치합니다. Arial Black 15 Italic/17은 14px 세트를 확대해 씁니다.
- 실행파일의 `HOME`·`AWAY`·색 이름(`translation/fix/skip_elf.json`)은 유니폼 텍스처 선택 키라 번역하지 않습니다.
- VRAM 제약(v1.1까지의 방식)
  - 폰트 텍스처 한 장은 4bpp 64KB가 한계입니다.
  - 게임은 TEX0의 CBP(CLUT 위치)와 CLUT 크기로 VRAM 할당량을 계산합니다. 그래서 텍스처를 키울 때는 CBP를 텍스처 뒤로 옮깁니다.
- **동적 글리프 캐시**
  - 텍스처는 매 프레임 RAM에서 VRAM으로 다시 올라갑니다.
  - 그래서 각 폰트 텍스처의 빈 칸을 슬롯으로 쓰고, 글자를 그릴 때 필요한 음절 비트맵을 LRU로 슬롯에 복사합니다. 복사는 비캐시 주소(`0x20000000|addr`)로 씁니다.
  - 실행파일 패치는 세 곳입니다(`tools/codepatch.py`).
    - 폰트 로더 `0x4dbbac`: 비트맵 세트 연결
    - 글자 폭 `0x4dbcf0`: 한글 진행 폭
    - 글자 그리기 `0x4dc39c`: 슬롯 배정과 복사
  - 새 코드는 쓰이지 않는 함수 자리 두 곳(`0x32cea0`~`0x32d190`, `0xb548a8`~`0xb54fe0`)에 넣었습니다.
- 메인 메모리 여유가 2~3MB뿐이라 음절 비트맵은 3세트만 두고 7개 폰트가 나눠 씁니다(약 1.15MB 증가). 크기 차이는 쿼드 확대·축소로, 이탤릭은 정점 기울임으로 맞춥니다.

## 검증 방법

- PCSX2 v2.2.0 휴대용 사본(`tools/emu.py`)을 백그라운드로 실행하고, 키 입력과 화면 캡처로 확인했습니다.
- `tools/freezetest.py`: 타이틀 → 빠른 경기 → 경기 진입 후 15초 간격으로 화면 4장을 찍어 같은 화면이 이어지면 멈춤으로 판정합니다. 타이틀 화면으로 돌아간 경우는 따로 판정합니다.
- `tools/experiment.py`: 빌드 설정별로 freezetest를 반복합니다.
